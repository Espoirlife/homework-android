## 1. 背景与目标

### 1.1 产品定位

一款面向**中小学教师**的**多班级学生作业统计工具**：围绕「布置作业 → 逐生记录完成/订正/评级 → 统计与导出」这一闭环，解决教师统计作业完成情况的低效问题。

四个关键属性：

- **单机离线**：无账号、无后端、无遥测，全功能离线可用。

- **本地优先**：数据存本机 Room(SQLite)，随卸载才丢失；仅用户主动配置 WebDAV 云盘时才联网。

- **移动原生**：利用原生相机扫码、系统打印、系统文件选择器、KeyStore 加密等能力。

- **隐私优先**：学生姓名等数据不出本机（除发往用户自己配置的云盘）。

### 1.2 背景

教师日常需要统计全班「谁交了作业、谁没交、谁订正了、质量如何」，传统做法是纸质名单打勾，存在重复劳动、易出错、难以汇总和留存的问题。一个网页版工具验证了这套「扫码 + 三项状态」的可行性，但网页形态受限于浏览器（数据易丢、移动场景不便）。本产品在 Android 原生上独立重做，不受上述形态限制。

### 1.3 产品目标

1. **核心能力完整**：覆盖班级、学生、作业、录入（完成·订正·评级三项）、二维码、扫码、报表、备份八大模块。
2. **体验原生**：原生相机扫码、系统打印、SAF 文件选择、KeyStore 凭据加密。
3. **数据更稳**：Room(SQLite) 本地持久化；WebDAV 原生直连，无浏览器同源/CORS 问题。
4. **隐私延续**：不联网、无账号、无遥测，数据不出本机（除用户主动配置的云盘备份）。

### 1.4 非目标（v1.0 不做）

- 不做账号体系与多设备云同步（数据策略已定为本地优先）。

- 不做 iOS / 专属平板布局（但自适应手机与平板宽屏）。

- 不做学生端/家长端协作，不做消息推送给他人。

- 不做多语言：仅中文界面（文案、报表、导出均中文）。

- 不做作业「拍照存证」能力（仅扫码录入，不附加图片证据）。

- 不做本地通知与提醒（无作业收齐提醒、无备份结果通知），因此不申请 `POST_NOTIFICATIONS` 权限；后台任务仅用于 WebDAV 上传失败后的静默重试，不产生用户可见通知。

- 不引入「免做 / 请假」状态：完成状态固定为三值，完成率分母按班级在册人数计算（见 FR-8.5）。

- 不承诺与任何第三方工具的格式兼容（二维码与备份格式均为本产品自有，见附录）。

## 2. 术语定义

| 术语    | 说明                                                  |
| ----- | --------------------------------------------------- |
| 班级    | 一个教学班，含名称、备注、学号编号规则                                 |
| 学生    | 班级成员，含序号（seq）、姓名、备注；学号（code）= 班级前缀 + 序号补零，展示时派生、不入库 |
| 作业    | 分配给某班级的一次作业，含标题、布置日期（备注为预留字段，v1.0 无录入入口）            |
| 作业记录  | 某学生某次作业的三项状态；仅在该生首次被录入时创建（见 FR-4.4）                 |
| 完成状态  | 已完成 / 未完成 / 部分完成                                    |
| 订正状态  | 讲解后订正 / 订正完成                                        |
| 评级    | A / B / C / 未评                                      |
| 二维码   | 学生身份二维码，内容协议见附录 A                                   |
| 完成率   | （已完成 + 部分完成）占应完成人数的比例，仅「未完成」不计入                     |
| 应完成人数 | 该作业所属班级**当前在册**的学生数，即完成率分母（见 FR-8.5）                |

## 3. 目标用户与场景

### 3.1 用户画像

- **主用户**：小学/初中教师、班主任。

- **班级规模**：一人管理 1~~10 个班级，每班 30~~60 名学生。

- **技术能力**：非技术用户，要求操作简单直接（导入建班、扫码即录）。

### 3.2 使用环境

- 教室（收作业扫码）

- 办公室（录入 / 统计 / 打印）

- 家中（整理报表与备份）

### 3.3 核心用户故事

- 作为教师，我希望**从 Excel 导入学生名单**快速建班，而不是逐个录入。

- 作为教师，我希望**收作业时用手机摄像头扫学生二维码**即可标记完成、订正、评级，不用翻名单。

- 作为教师，我希望**一键生成全班二维码并打印 A4 贴纸**贴在作业本封面。

- 作为教师，我希望**随时查看某份作业的完成率、未完成名单、待订正名单**，并导出 Excel 发给家长/存档。

- 作为教师，我希望**数据自动备份到自己的网盘（WebDAV）**，换手机也能恢复。

## 5. 功能需求（FR）

### 5.1 首次启动与引导

- FR-1.1 首次启动显示引导页，引导创建第一个班级（名称 + 可选备注 + 学号编号规则 + 回收空号开关）。

- FR-1.2 创建完成后进入「班级」页，置为当前班级。

- FR-1.3 已引导标记持久化，二次启动直接进入主界面。

### 5.2 班级管理

- FR-2.1 「班级」页以卡片列表展示（副标题为「N 名学生 · M 份作业」），点击卡片进入该班级的「学生名单」下级页并置为当前班级；作业 / 报表 / 录入 / 二维码打印页顶栏设班级下拉，可切换当前班级。

  - v0.7 修订，有意偏离原型：原型为「班级 / 学生」两个页签，点击卡片展开前 6 名学生预览。安卓端改为两级导航——班级页只列班级，点击进入独立的学生名单页（顶栏显示班级名并带返回）。原因：页签方案下学生页依赖全局「当前班级」，与卡片展开预览的信息重复；两级结构层次更清晰，且学生名单按 `classId` 绑定，不受别处切换当前班级影响。

- FR-2.2 新建班级：表单含名称、学号规则（前缀、补零位数 1–4、回收空号开关）与示例学号实时预览；备注不在新建表单中。

- FR-2.3 长按班级卡片打开「班级设置」菜单：修改班级名称、修改备注、学号规则、一键重排学号、删除班级；删除需二次确认并级联删除其学生、作业、记录，若删除的是当前班级则自动切换到剩余第一个班级。

- FR-2.4 班级卡片副标题显示该班学生数与作业数，右侧为进入下级页的箭头；学生名单页顶部显示「共 N 人」。

### 5.3 学生管理

- FR-3.1 学生列表按序号（seq）排序，展示学号、姓名、备注；点击学生打开操作菜单：修改姓名、修改学号序号、修改备注、删除学生。

- FR-3.2 学号自动编号：格式 `前缀 + 序号(补零到指定位数)`，补零位数 1–4；学号仅展示派生，库内只存序号。

- FR-3.3 支持「回收空号」：删除学生后，新增学生优先占用最小空号。

- FR-3.4 单个学生序号可手动改写（1–9999），改后重算学号并校验重号（重复需提示「序号 N 已被 XX 占用」）。

- FR-3.5 一键重排全班学号：按当前顺序重编为 1..N。

  - 重排不影响已打印二维码的定位正确性（二维码按 `studentId` 定位，见附录 A）；

  - 二次确认弹窗须提示「已打印贴纸上的学号将与系统不一致，建议重新打印」。

- FR-3.6 Excel 导入名单：

  - 从系统文件选择器（SAF）选取 `.xlsx/.xls`；

  - 第一行为表头，自动识别「姓名列」（命中规则见附录 B）与可选「备注列」，允许手动改列；

  - 同名（本班已存在）学生标记为重复并跳过；

  - 导入前预览，确认后批量写入。

- FR-3.7 删除学生需二次确认，并级联删除其作业记录。

### 5.4 作业管理

- FR-4.1 作业列表按布置日期倒序；列表行展示标题、日期（MM月DD日）、完成率、待订正数与「已计入/在册」计数。

- FR-4.2 布置作业：输入标题，日期默认当天；布置后直接进入该作业录入页。

- FR-4.3 长按作业卡片打开「作业设置」菜单（v0.5 扩展，有意偏离原型）：

  - **修改作业名称**：输入弹窗预填当前标题，空值不可保存；

  - **修改布置日期**：输入弹窗预填当前日期，严格校验 `yyyy-MM-dd` 格式（非法日期拒绝保存）；

  - **删除作业**：需二次确认，提示将一并删除的录入记录条数，确认后级联删除该作业全部记录；

  - 录入记录以 `assignmentId` 关联，修改名称/日期不影响已录数据；作业列表、报表、导出均响应式同步。

- FR-4.4 新建作业时不预生成学生记录。录入页与报表以「班级在册学生 + 该作业已有记录」合并呈现：

  - 尚无记录的学生按 `settings` 的 `defaultCompletion` / `defaultCorrection` 显示（默认「未完成 / 讲解后订正」），评级恒显示为「未评」；

  - 该生被首次改动任一项时才落库一条记录；

  - 作业创建后新导入的学生自动出现在旧作业名单中，无需补齐动作。

### 5.5 作业录入

- FR-5.1 进入某作业的录入页，列表展示全班学生及各自三项状态。

- FR-5.2 每生三项独立可改：

  - 完成状态：已完成 / 未完成 / 部分完成；

  - 订正状态：讲解后订正 / 订正完成；

  - 评级：A / B / C / 未评（可留空）。

  - 交互：状态标单击循环切换，长按打开直选列表（首次使用 3 次循环后提示长按可直选）。

- FR-5.3 批量设置：顶部批量面板可多维度同时选，「应用到全班 N 人」一次写入，「清空选择」重置。该操作视为对全班的显式改动，会为尚无记录的学生一次性落库记录。

- FR-5.4 每次改动自动保存（无记录则新建、已有则更新），无需手动保存按钮。

- FR-5.5 录入页顶部展示三项统计：完成率、待订正、未完成。

### 5.6 二维码生成与打印

- FR-6.1 为每名学生生成二维码，内容遵循自有协议（见附录 A）。

- FR-6.2 二维码参数可配置：每行个数（2–8）、页边距（5/8/10/15 mm，默认 8 mm）、纠错级别（L/M/Q/H）、是否包含学号；纸张固定 A4。

  - 边距下限 5 mm（v0.6 修订，有意偏离原型）：原型为浏览器打印，浏览器会自行叠加默认页边距，故原型可用 0/1/2/4 mm；安卓端用系统打印框架直接映射物理纸张，无此缓冲，边距过小会落入打印机不可打印区（常见机型 3\~5 mm），导致最外圈二维码被裁切或整页被驱动强制缩放。读取到历史小于 5 mm 的存量配置时，排版按 5 mm 兜底。

- FR-6.3 排版（v0.6 修订）：按「每行几个 × N 行」网格展示，行数 N 由页面可用高度与单张贴纸实高自适应计算得出，纵向铺满 A4 后再翻页（不再固定 4 行）；每张贴纸上方二维码、下方姓名 + 学号（学号按开关显示），四周绘制虚线裁切框；二维码边长按列宽自适应，位图按绘制尺寸过采样生成以保证打印清晰度；预览页标注「A4 排版预览 · N × M = K 枚/页 · 共 X 人 · 虚线为裁切边」，预览与打印共用同一套排版参数。

- FR-6.4 打印：调用系统打印 API，A4 纵向，仅输出二维码网格（自动隐藏导航/按钮）；打印页提供「预览 / 打印」按钮与顶栏打印图标。

- FR-6.5 二维码打印页从「设置 · 二维码」入口进入，页内自带班级选择器与排版参数（v0.6 修订：排版参数由设置页迁入本页，与预览同屏，调参即时可见）。

### 5.7 扫码录入

- FR-7.1 在作业录入页进入扫码模式，调用后置摄像头实时识别二维码。

- FR-7.2 解析成功后按「班级 ID + 学生 ID」定位当前班级学生；旧版四段二维码回退为「班级 ID + 学号」定位。定位失败（非本班/无此人/学生已删除）给出提示并不写入。

- FR-7.3 扫码可一次写入完成状态、订正、评级三项；未勾选的项保持原样。

- FR-7.4 「扫到即标记为」预设完成状态，扫中即写入并自动保存。

- FR-7.5 相同内容 1.5s 内去重，避免同一张码连续触发多次。

- FR-7.6 支持前后摄像头切换、开启/停止扫码。

- FR-7.7 取景框（v0.6 修订）：取景区为居中的圆角正方形（无四角角标）；相机异步初始化，不阻塞页面转场；离开扫码页时主动释放相机会话，避免预览画面残留到录入页。

### 5.8 统计报表

- FR-8.1 报表页含两个页签：单次作业 / 个人报表，默认停在「单次作业」。

  - v0.7 修订：移除「班级报表」页签（原含三项统计、近 5 次完成率柱状图、未完成学生列表与导出）。原因：其统计信息与单次作业页签重复，柱状图在小屏上信息密度低；教师实际使用以「按某次作业核对」和「看某个学生历次表现」两条路径为主。数据层的班级汇总能力（`classSummary` / `missListFlow`）保留，未来如需以其他形式呈现可直接复用。

- FR-8.2 单次作业页签：作业选择器；完成率、已完成、部分完成、待订正四项统计；完成情况明细表（学号 / 姓名 / 完成情况 / 订正情况 / 评级）；底部「发送到… / 导出 Excel」两个按钮。

- FR-8.3 个人报表：学生选择器；个人完成率、已完成、未完成三项统计；逐次明细表（作业 / 日期 / 完成情况 / 订正情况 / 评级）；底部「发送到… / 导出 Excel」两个按钮。

- FR-8.4 作业录入页导出（v0.7 新增）：录入页在三项统计卡与「学生记录」之间提供「发送到… / 导出 Excel」按钮，导出内容与 FR-8.2 的完成情况表完全一致，免去为导出单次作业而跳转报表页。

- FR-8.5 完成率口径：分子为「已完成 + 部分完成」，仅「未完成」不计入；分母为该作业所属班级**当前在册**学生数（含尚无记录的学生，其按默认值计入未完成）。

  - 已知副作用：删除学生后，历史作业的完成率分母随之减小，历史报表数字会变化。v1.0 接受此行为，不做布置时人数快照。

- FR-8.6 报表导出为 `.xlsx`。个人报表列宽按中文内容自适应（中文按 2 字符宽、上限 40）；单次作业完成情况表套用固定版式，见 FR-8.8。

- FR-8.7 导出有两个出口：「导出 Excel」走系统文件保存（SAF），自行选择保存位置；「发送到…」走系统分享面板（v0.7 新增），文件经 `FileProvider` 授权后可直接交给金山文档 / WPS、微信、邮件等应用。

  - 金山文档不提供 WebDAV，其开放平台 API 需公网回调地址与服务端签名，与本产品「单机离线、无账号体系」的定位冲突；因此以系统分享作为对接方式，由用户在分享面板中选择目标应用完成上传。

- FR-8.8 单次作业完成情况表导出：在报表页「单次作业」页签或作业录入页触发，导出该作业逐生完成情况表。版式对齐「作业登记表」模板（v0.7 修订）：

  - 第 1 行为合并居中标题「班级 备注 日期 作业登记表」（班级无备注时省略该段），微软雅黑 16 加粗；

  - 第 2 行为表头，第 3 行起为数据，列为「序号 / 姓名 / 完成情况 / 评级 / 订正情况 / 备注」，序号为 1 起流水号、备注列留空供手写；

  - 表头与数据同款（华文中宋 14、纯黑细边框、水平垂直双居中），A–F 列等宽 13.64 字符，行高 19.5；

  - 无记录学生按默认值呈现（同 FR-4.4）。文件出口同 FR-8.7。

- FR-8.9 明细表排版（v0.6 补充）：FR-8.2 / FR-8.3 两张明细表的表头与数据行采用固定列宽 + 等宽列间距，表头与数据列对齐方式一致（完成情况/订正情况居中、评级右对齐）；评级列未评时单元格留空而非显示「未评」，以降低表格视觉噪音。

### 5.9 设置

- FR-9.1 记录默认值：默认完成状态、默认订正状态。修改后立即作用于所有尚无记录的学生（含历史作业），已落库的记录不受影响；评级永远默认「未评」。

- FR-9.2 二维码：提供「二维码打印」入口（排版参数已于 v0.6 迁至打印页内，见 FR-6.5）。

- FR-9.3 云同步：WebDAV 配置入口、自动备份开关与上次上传时间。

- FR-9.4 数据管理：导出备份文件、从文件恢复。

  - v0.6 修订：移除「清空全部数据」入口。该操作破坏性强且与「从文件恢复」的覆盖语义重叠，教师误触代价过高；如需清空，可通过恢复一份空白备份实现。

- FR-9.5 关于：版本号与权限说明（仅相机）。

### 5.10 备份与恢复

- FR-10.1 手动导出：生成自有格式 JSON 备份（`hwt-backup`，含 version/exportedAt，见附录 D）。

- FR-10.2 手动导入：校验备份格式后全量覆盖，导入前二次确认。

- FR-10.3 WebDAV 自动备份：任意数据变更后延迟 8s 合并上传一次（连续操作合并）。

- FR-10.4 云端备份列表：读取并列出云端备份，支持「下载并恢复」。

- FR-10.5 保留份数：超出保留份数的最旧备份自动删除。

- FR-10.6 凭据安全存储：WebDAV 密码用 Android KeyStore 加密保存（见附录 C）。

## 6. 数据模型（Room）

| 实体            | 字段                                                                                                                                                                                  | 主键/索引                                                      |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `settings`    | id(='app')、currentClassId、onboarded、defaultCompletion、defaultCorrection、qr(perRow,margin,level,withNo)、autoBackup、lastBackupAt、webdav(enabled,url,username,password,keep,lastError) | id                                                         |
| `classes`     | id、name、note、numbering(prefix,digits,recycle)、createdAt、updatedAt                                                                                                                   | id                                                         |
| `students`    | id、classId、seq、name、note、createdAt、updatedAt                                                                                                                                        | id；索引 classId                                              |
| `assignments` | id、classId、title、assignedDate、note、createdAt、updatedAt                                                                                                                              | id；索引 classId                                              |
| `records`     | id、assignmentId、studentId、classId、completion、correction、grade(nullable)、comment(nullable，v1.0 预留)、updatedAt                                                                         | id；**唯一索引 (assignmentId, studentId)**；索引 studentId、classId |

### 6.1 字段类型约定

| 类别    | 类型                       | 说明                                                                                     |
| ----- | ------------------------ | -------------------------------------------------------------------------------------- |
| 主键 id | `String`（UUID v4）        | `settings.id` 固定为 `'app'`；UUID 避免跨设备备份恢复时的 id 空间冲突                                     |
| 外键    | `String`                 | 指向对应表主键                                                                                |
| 时间戳   | `Long`（epoch millis，UTC） | `createdAt`/`updatedAt`/`lastBackupAt` 等；可直接参与索引与范围比较                                  |
| 布置日期  | `String`（`yyyy-MM-dd`）   | `assignments.assignedDate` 为纯日期语义，不携带时刻                                                |
| 学号    | 不入库                      | `code` 为展示派生值 = `classes.numbering.prefix + pad(seq, digits)`；库内仅存 `seq`，改号/重排只改 `seq` |
| 枚举    | `String`                 | 完成/订正/评级存稳定字符串常量，不存序号，避免枚举顺序调整破坏历史数据                                                   |

备份 JSON 中时间戳序列化为 ISO-8601 字符串以保持可读，导入时转回 `Long`（见附录 D）。

### 6.2 关系与约束

- `class -> students / assignments / records`：一对多，删除班级级联删除子表（Room `@Relation` + 事务，或外键 `onDelete=CASCADE`）。

- `records` 在 `(assignmentId, studentId)` 上建唯一索引：一名学生在一份作业下最多一条记录。写入统一走 upsert（`OnConflictStrategy.REPLACE` 或 `ON CONFLICT DO UPDATE`），使 FR-5.4 自动保存与 FR-7.5 扫码去重窗口的并发写入不产生重复行。

- `records` 懒创建（见 FR-4.4）：作业创建时不写入任何记录行。Repository 以「班级在册学生 LEFT JOIN 该作业记录」返回统一视图对象，缺失记录的字段由 `settings` 默认值填充，JOIN 逻辑不外泄到 ViewModel。

- `records.comment` 与 `assignments.note` 为 v1.0 预留字段，无录入入口，恒为 null/空串，不在任何 FR 中出现。

- 备份 JSON 为应用自有 schema，含 `format`/`version` 字段，支持向后兼容迁移。

### 6.3 Schema 迁移策略

- 开发期（M1 至首个对外 Release 之前）：开启 `fallbackToDestructiveMigration()`，允许自由调整实体结构。

- 首个对外 Release 起：schema 冻结为 `version = 1`，关闭销毁式回退，此后每次结构变更手写 `Migration`。

- 全程开启 `exportSchema = true`，生成的 schema JSON 随代码入版本库，作为迁移正确性的比对依据。

- 销毁式回退在有真实用户数据后等同静默清空教师全学期数据，与第 8 节稳定性要求冲突，因此冻结时点挂在「首个对外 Release」而非固定里程碑。

## 7. 核心用户流程

**① 首次启动引导**
首启 → 引导页 → 创建第一个班级（名称 + 备注 + 编号规则 + 回收空号）→ 标记已引导 → 进入「班级」页。

**② 建班与导入名单**
新建班级 → 设置学号编号规则 → 从系统文件选择器选 Excel → 自动识别姓名/备注列（可手动改）→ 预览（重复项跳过）→ 确认批量写入 → 自动编号完成。

**③ 布置作业与录入**
切换目标班级 → 布置作业（标题，日期默认当天）→ 进入录入页 → 全班按默认值显示「未完成/讲解后订正」（尚未落库）→ 批量设默认值或逐生勾选三项 → 首次改动即创建记录并自动保存。

**④ 收作业扫码录入（核心场景）**
二维码打印页（设置子页）生成并打印贴纸 → 贴作业本封面 → 收作业时打开该作业录入页 → 进扫码模式 → 预设「扫到即标记为」（及可选订正/评级）→ 扫中即写入并保存（1.5s 去重）。

**⑤ 统计与导出发送**
进入报表页 → 「单次作业」选定某次作业逐生核对，或「个人报表」看某生历次明细 → 导出 xlsx →「导出 Excel」保存到本地，或「发送到…」交给金山文档 / WPS 等应用。作业录入页也可直接导出当次完成情况表。

**⑥ 备份与恢复**
设置页配置 WebDAV（目录/账号/密码/保留份数）→ 测试连接 → 之后数据变更延迟 8s 自动合并上传 → 需要时「读取备份列表 → 下载并恢复」；同时支持手动 JSON 导出/导入。

## 8. 非功能需求（NFR）

| 维度    | 要求                                                                         |
| ----- | -------------------------------------------------------------------------- |
| 离线    | 全部功能离线可用，无任何网络依赖（WebDAV 备份除外）                                              |
| 隐私    | 无遥测、无第三方统计 SDK、无联网上传；仅用户主动配置的 WebDAV 请求                                    |
| 权限最小化 | 仅相机（扫码）；文件读写走 SAF 无需存储权限（见第 11 节）                                          |
| 性能    | 单班 60 人、100 份作业规模下，列表滚动/报表生成不卡顿；扫码识别 < 300ms                               |
| 兼容    | 最低 Android 8.0（API 26），适配 Android 15；支持手机竖屏 + 平板宽屏                         |
| 稳定性   | 数据写入采用事务，崩溃不丢已保存内容                                                         |
| 安全    | 密码 KeyStore 加密；备份文件不含明文凭据                                                  |
| 可维护   | MVVM + Repository + Room，模块分层清晰（见第 9 节）                                    |
| 视觉一致  | 全屏页面走系统栏沉浸（内容背景延伸至屏幕物理边缘，交互元素避让状态栏与导航条）；异步数据加载期不渲染空态占位，避免冷启动/切页闪烁（v0.6 补充） |

## 9. 技术方案概述

| 关注点      | 选型                                                                | 说明                                                        |
| -------- | ----------------------------------------------------------------- | --------------------------------------------------------- |
| 语言/UI    | Kotlin + Jetpack Compose + Material 3                             | 声明式 UI，代码风格现代                                             |
| 架构       | MVVM + Repository + 单向数据流（StateFlow）                              | ViewModel 持有 UI 状态，Repository 收敛数据                        |
| 本地库      | Room（SQLite）                                                      | 5 张表 + 关系映射与级联删除；主键 String UUID、时间戳 Long（见 6.1）；迁移策略见 6.3 |
| 依赖注入     | Hilt                                                              | ViewModel/Repository 依赖注入                                 |
| 导航       | Navigation Compose                                                | 4 个底部 Tab 主页面 + 引导/录入/扫码/二维码打印/WebDAV/备份/导入向导等子页面         |
| 二维码生成    | ZXing core（`com.google.zxing:core`）                               | 生成二维码位图                                                   |
| 扫码       | CameraX + Google ML Kit Barcode Scanning                          | 原生相机，识别快；无 GMS 时回退 ZXing                                  |
| Excel 读写 | Apache POI（`poi-on-android`）                                      | 解析 xlsx 导入 / 生成 xlsx 导出                                   |
| 文件存储     | Storage Access Framework（SAF）                                     | 导入 Excel、导出 xlsx/json 走系统选择器                              |
| 打印       | Android Print Framework（PrintManager）                             | A4 二维码贴纸打印                                                |
| WebDAV   | OkHttp + 手写 WebDAV 动词（PROPFIND/PUT/MKCOL/DELETE）或 sardine-android | 原生直连，无 CORS 限制                                            |
| 凭据存储     | Android KeyStore + EncryptedSharedPreferences                     | 密码加密保存                                                    |
| 备份调度     | 防抖（8s）+ WorkManager（仅失败重试）                                        | 数据变更后延迟合并上传；重试静默进行，不发通知                                   |

关键设计决策：

1. **WebDAV 直连**：原生 App 不受浏览器同源策略限制，无需任何本地转发/代理端点，App 直连目标服务器。
2. **系统打印**：用 `PrintManager` 输出 A4 二维码网格，替代浏览器打印。
3. **扫码去重**：相同内容 1.5s 内不重复触发，避免扫到同一张贴纸连写多次。
4. **二维码协议自有**：`HWT|班级ID|学生ID|学号|姓名`（完整班级 ID，按学生 ID 定位，见附录 A），不追求与任何外部工具兼容。
5. **记录懒创建**：作业创建时不预生成记录，首次录入才落库，配合 `(assignmentId, studentId)` 唯一索引以 upsert 写入（见 6.2）。

## 13. 验收标准（v1.0 准入）

1. 新建 3 个班级，每班从 Excel 导入 40+ 学生，学号编号/改号/重排均符合规则且无重号。
2. 建 10 份作业，对全体学生录入三项状态，完成率/待订正/未完成名单与手动核对一致。
3. 打印本班二维码，用另一台手机扫码能准确定位学生并写入三项（含 1.5s 去重）；执行一键重排学号后，原贴纸仍定位到同一学生。
4. 导出个人报表与单次作业完成情况表 `.xlsx`，用 Excel/WPS 正常打开，版式与列宽正常；「发送到…」能将文件交给金山文档 / WPS。
5. 配置 WebDAV 后：改动数据 → 8s 内自动生成备份；恢复某份云端备份后数据完整。
6. 导出的 `.json` 备份可被本应用再次导入，数据完整；格式标记与版本号正确。
7. 全程离线（断开网络）核心功能可用；无任何遥测/第三方统计流量。
8. Android 8.0 \~ 15 设备上安装、运行、扫码、打印均正常。

## 14. 风险与开放问题

| # | 风险/问题                                | 影响            | 建议                                      |
| - | ------------------------------------ | ------------- | --------------------------------------- |
| 1 | WebDAV 服务端多样（Nextcloud/坚果云/自建），兼容性差异 | 备份失败          | 提供「测试连接」+ 明确错误码提示；优先验证坚果云、Nextcloud、群晖  |

## 附录

### 附录 A：二维码内容协议（自有）

- 内容：`HWT|<classId>|<studentId>|<code>|<name>`（`classId` 班级完整唯一 ID、`studentId` 学生完整唯一 ID、`code` 学号、`name` 姓名）。

- 解析：以 `|` 切分，`parts[0] === 'HWT'` 且长度 ≥ 4 为合法。

  - 长度 ≥ 5：`parts[1]` 班级 ID、`parts[2]` 学生 ID、`parts[3]` 学号、`parts[4..]` 拼接为姓名。

  - 长度 = 4（旧版四段码）：`parts[1]` 班级 ID、`parts[2]` 学号、`parts[3..]` 拼接为姓名。

- 定位：优先用「班级 ID + 学生 ID」定位；旧版四段码回退用「班级 ID + 学号」定位。班级 ID 不匹配提示「非本班二维码」，学生已删除提示「未找到该学生」。

- 设计说明：

  - 使用**完整**班级 ID（不做截断），避免不同班级 ID 前缀相同导致的碰撞；

  - 以 `studentId` 而非 `code` 作为定位键，因学号可被 FR-3.4 改号与 FR-3.5 重排修改，已打印贴纸若按学号定位会在重排后指向错误学生；`studentId` 为主键不可变；

  - `code` 与 `name` 仅用于扫码结果界面回显；若 M3 实测在最小尺寸 + H 级纠错下识别率不足，可将 `name` 从码内容中移除（姓名已印在贴纸下方文字）。

### 附录 B：Excel 导入识别规则

- 姓名列表头命中（精确 → 模糊）：学生姓名 / 姓名 / 名字 / 学生 / name / student / studentname / fullname；未命中默认取第一列。

- 备注列表头命中：备注 / 说明 / 注释 / note / remark / comment；未命中无备注列。

- 逐行读取，空行跳过；同一班级已存在的同名学生标记重复并跳过。

### 附录 C：凭据安全

- WebDAV 密码使用 Android KeyStore 加密后写入 EncryptedSharedPreferences/DataStore；内存中仅在发起备份时短暂使用；备份 JSON 不包含 WebDAV 密码。

### 附录 D：备份文件格式（自有）

- `format`: `hwt-backup`；`version`: 1；`exportedAt`: ISO 时间。

- `data`: 含 `settings / classes / students / assignments / records` 五个数组，字段与第 6 节数据模型一致。

- 序列化约定：主键与外键为 UUID 字符串原样输出；库内 `Long` 时间戳序列化为 ISO-8601 字符串，导入时转回 `Long`；`assignedDate` 保持 `yyyy-MM-dd`。

- `records` 数组仅包含实际落库的记录，不含懒创建未生成的行；恢复后未落库学生仍按当前 `settings` 默认值显示。

- 导入校验：`format === 'hwt-backup'`，否则拒绝并提示「备份文件格式不正确」。

- 备份不含 WebDAV 密码（见附录 C）。
